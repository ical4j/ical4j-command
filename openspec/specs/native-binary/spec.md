# native-binary Specification

## Purpose
How `ict` is built and released as a single native executable: versioned reachability
metadata, the native smoke suite that gates the registry, startup time, and release artifacts.
## Requirements
### Requirement: The build produces a native executable
The Gradle build SHALL produce a GraalVM native executable named `ict` via the `nativeCompile` task. The JVM distribution (`installDist`) SHALL remain buildable from the same module for debugging and for platforms without a native toolchain.

#### Scenario: Native compile succeeds
- **WHEN** `./gradlew nativeCompile` runs on a supported platform with GraalVM installed
- **THEN** `build/native/nativeCompile/ict` exists and `ict --version` prints the build version

#### Scenario: JVM fallback
- **WHEN** `./gradlew installDist` runs
- **THEN** `build/install/ict/bin/ict --version` prints the same version

### Requirement: Reachability metadata is versioned in the repo
Reflection, resource, serialization and proxy metadata required by dependencies SHALL be checked in under `src/main/resources/META-INF/native-image/org.ical4j/ict/`. picocli command metadata SHALL be generated by picocli-codegen at compile time. Metadata for ical4j, Jackson and the MCP SDK SHALL be captured with the tracing agent and reviewed before commit.

#### Scenario: Timezone resources reachable
- **WHEN** the native `ict export calendar` runs for a collection whose events use `Australia/Melbourne`
- **THEN** the VTIMEZONE is emitted correctly and no missing-resource error occurs

#### Scenario: ServiceLoader factories reachable
- **WHEN** the native binary parses an iCalendar stream containing an `X-` property and an extension component
- **THEN** ical4j's factories resolve them as they do on the JVM

### Requirement: Native smoke suite gates the registry
A smoke suite SHALL run against the native binary in CI and SHALL invoke `--help` plus one real invocation for every registered operation, and one `ict mcp` handshake. A registered operation absent from the suite MUST fail the build.

#### Scenario: Smoke run
- **WHEN** the native smoke suite runs
- **THEN** every operation in the registry has been executed at least once against the binary and all exits match the CLI exit-code contract

### Requirement: Startup time
`ict --help` on the native binary SHALL complete in under 100 ms on the CI linux x64 runner, measured as wall-clock over ten runs and reported in the build log.

#### Scenario: Startup measurement
- **WHEN** the CI native job finishes
- **THEN** the log reports the median `ict --help` wall time and the job fails if it exceeds 100 ms

### Requirement: Release artifacts
On a version tag, CI SHALL build native executables for linux x64, linux arm64, macOS arm64 and windows x64 and attach them to a GitHub Release as `ict-<version>-<os>-<arch>` (with `.exe` on windows) together with SHA-256 checksums. The single jar SHALL continue to publish to Maven Central.

#### Scenario: Tagged release
- **WHEN** the tag `ict-1.0.0` is pushed
- **THEN** the GitHub Release for that tag carries four executables and a checksum file, and Maven Central receives `org.ical4j:ict:1.0.0`
